Program contract ​

Every program that OpsTruss runs, from a unit, a task, a step, or a plugin, gets its inputs and gives its results the same way. This page is what a script or a plugin can rely on.

In ​

WhatHolds
INPUT_<NAME>Each input of the task or plugin, in uppercase with - as _; a list or a map as JSON. An input over 64 KiB is only in OPSTRUSS_INPUTS
OPSTRUSS_INPUTSA JSON file with every input in its own type; mode 0600, removed after the call
OPSTRUSS_STATEFor a program of a unit: a JSON file with the last outputs and inputs that succeeded, and an attempt that did not finish; for destroy, those of what it takes away
stdinWhat stdin: writes
argumentsFor the exec hook only: what follows -- in opstruss exec

INPUT_* reaches the program that is the body of a task or a plugin. A run inside steps: gets values through env:, so each value reaches only the program that names it.

Out ​

WhatMeans
exit code0 is success, anything else failure; a program killed by a signal exits with 128 plus its number, as in a shell
OPSTRUSS_OUTPUTA file of outputs: name=value lines, name<<EOF … EOF for several lines, or one JSON object, which keeps types
OPSTRUSS_PLANFor plan only, optional: the changes, the outputs that change, a digest, and whether the plan is exact
OPSTRUSS_RESULTOptional: {"changed": false, "message": "…", "sensitive": ["<output>"]}; without changed, the program changed something
stdout, stderrThe log of the run; also an output with from: stdout or from: stderr
text
image=ghcr.io/acme/app:1.2
notes<<EOF
first line
second line
EOF

A text value is read by the type of its output, so port=8080 is a number for an output of type integer.

Plans ​

A plugin's plan writes $OPSTRUSS_PLAN:

json
{
  "changes": [{"action": "create", "resource": "web", "sensitive": false}],
  "outputs": ["services"],
  "digest": "sha256:…",
  "exact": true
}
  • action is create, update, delete, replace, or run.
  • digest is a hash of what will be applied, the actions and their values, not of a plan file: the same for the same state and inputs, so a plan made again in another run matches. OpsTruss joins it with the digest of the definition of the unit.
  • exact: true is a promise: up applies exactly the changes whose digest is $OPSTRUSS_DIGEST, from a plan it kept in OPSTRUSS_WORKDIR or OPSTRUSS_TEMP, or fails when a new plan differs, as a saved plan of Terraform. A plugin that cannot promise it writes exact: false, and an approval holds only for an exact plan.
  • A plan that writes nothing means that the unit runs.

Where ​

VariableIs
working directoryThe directory of the file that writes the unit or task, or its dir:
OPSTRUSS_PLUGIN_DIRThe directory of the plugin; for programs of plugins only
OPSTRUSS_WORKDIRThe work directory of the unit, used under its lock; a cache that may be empty at any call, as in CI, except between plan and up of the same turn
OPSTRUSS_ARTIFACTSA directory for files that the record of the run keeps
OPSTRUSS_TEMPThe temporary directory of the run, shared by its programs; removed when the run ends
OPSTRUSS_STATE_DIRFor a plugin with state: tool on the local backend: the tool/ directory of the unit
OPSTRUSS_STATE_KEYThe lasting identity of a unit, such as prod/zone.7f3a9c1e, which stays when the unit moves; empty in the plan of a unit without a record

Facts ​

VariableIs
OPSTRUSS_PROJECT, OPSTRUSS_STACKThe project and the stack
OPSTRUSS_ADDRESSThe address of the unit, such as prod/web
OPSTRUSS_TASK, OPSTRUSS_RUNThe task, and the id of the run
OPSTRUSS_RUN_PARENTSThe ids of the runs that started this one, nearest last
OPSTRUSS_REASONWhy the unit runs: changed, requested, forced, or interrupted for one whose last attempt did not finish; a value it does not know reads as changed
OPSTRUSS_DIGESTThe digest of the plan that was approved
OPSTRUSS_SERVICE_IDFor a program that the daemon keeps running: an id that its children carry too
OPSTRUSS_CONTRACTThe version of this contract, 1; it goes up only for a change that breaks programs

Not every program runs inside a run or for a unit:

  • Every program gets the environment below, OPSTRUSS_CONTRACT, OPSTRUSS_PROJECT, and OPSTRUSS_STACK.
  • A program that ends inside a run, as a task, a step, a run unit, or a secret source, also gets OPSTRUSS_RUN, OPSTRUSS_RUN_PARENTS, OPSTRUSS_TASK, OPSTRUSS_REASON, OPSTRUSS_TEMP, the contract files, and OPSTRUSS_ARTIFACTS, except a secret source.
  • A program of a unit gets OPSTRUSS_ADDRESS and OPSTRUSS_STATE_KEY; one under the lock of the unit, as plan, up, destroy, and the exec hook, also gets OPSTRUSS_WORKDIR, OPSTRUSS_STATE, and OPSTRUSS_STATE_DIR. The status and logs tasks of a plugin run without the lock, so they get OPSTRUSS_STATE and OPSTRUSS_STATE_DIR to read, without OPSTRUSS_WORKDIR.
  • A program that lives outside a run, as a service and the source of a watch, gets inputs through INPUT_* only, and OPSTRUSS_SERVICE_ID.

Environment ​

A program starts from a clean environment: PATH, with the binaries of the plugin first, HOME, USER, LANG, LC_*, TZ, TMPDIR, TERM, the proxy variables, SSL_CERT_*, and SSH_AUTH_SOCK. To that come the variables that env: sets, and those of the environment of OpsTruss that pass: lets through; for a plugin, only those that its env: asks for, by name or by pattern. OPSTRUSS_* and INPUT_* come only from OpsTruss: env: cannot set them and pass: never passes them.

The output of a program is a pipe, not a terminal, so most tools leave out color. OpsTruss sets NO_COLOR=1 when the output of the run has no color, or when an output reads the stream of the program; a tool that colors with a flag, as tofu, can color when NO_COLOR is not set. env: {FORCE_COLOR: "1"} asks a tool for color.

Stopping ​

At cancel or timeout, stop.signal (SIGINT by default) goes to the process group of the program; after stop.grace (1m by default) the group is killed. Processes left in the group when the program ends, such as server & in a script, are stopped the same way before the lock of the unit is let go, as systemd does with KillMode=control-group.

The lock of the run is the inherited file descriptor 3, which a shell and Go pass on to children; a run that starts after OpsTruss died waits while a program of the old run still holds it, or still carries OPSTRUSS_RUN=<id> in its environment.
